### 3.2 正Vtest在PWM2下的实际命令符号

定义相电流正方向为**逆变器桥臂流向电机**。忽略死区和器件压降，仅推导理想PWM平均电压。

电阻校准β=0，令`m=Vtest/((2/3)Vbus)>0`。SVM给出：

\[
t_A=(1-m)/2,\quad t_B=t_C=(1+m)/2.
\]

PWM2、高有效主输出的高侧占空比为`D=1−t`，所以A的占空比更高，且：

\[
V_{AN}=\frac23mV_{bus}=Vtest>0.
\]

因此不能看到PWM2就额外给电流或电压取反。这里的Vtest仍是模型命令，不是已经测到的端电压；电流与本次计算的下一时刻命令也不能当作无延迟同时施加。

### 3.3 原理图放大器和B/C映射

| 路径 | 图纸连接 |
|---|---|
| B分流 | R38=0.5mΩ；上端SL1_B/DS1_N经R28=100Ω到U4 SN1(pin33)，SP1(pin32)接DS1_P/PGND侧 |
| B输出 | SO1(pin25)→R29=4.7Ω→M0_SO_N→PC0/ADC2_IN10 |
| C分流 | R39=0.5mΩ；上端SL1_C/DS2_N经R31=100Ω到SN2(pin31)，SP2(pin30)接DS2_P/PGND侧 |
| C输出 | SO2(pin26)→R30=4.7Ω→M0_SO_P→PC1/ADC3_IN11 |
| 电机端子 | U17：1=C、2=B、3=A；并非端子1/2/3依次A/B/C |

`M0_SO_N/P`是两路独立采样网名，不是差分对。图纸没有显示SP/SN反接或B/C互换。DRV公式带负号：

\[
V_{SO}=V_{REF}/2-G(V_{SN}-V_{SP}).
\]

vector0低侧导通时，正相电流从PGND经分流电阻流向低侧MOS/电机端，因此`V_SN−V_SP=−I_phase R_s`，得到：

\[
V_{SO}-V_{offset}=+G R_s I_{phase}.
\]

原生`Drivers/DRV8301/drv8301.cpp:43`起明确配置6×PWM模式，初始化写入后回读控制寄存器；这与图纸六路INH/INL连接对应。软件ADC正斜率与此一致。**图纸+软件符号链自洽，不支持直接反转电流。** 实际装配、接插件、电流物理方向仍没有独立证据。

仅交换B/C会使β反号，但α=−B−C不变；所以它不能单独解释本次两路计数共同上升的α负跳。

以TIM8下端更新为t=0：

| 相对时间 | 事件及用途 |
|---|---|

\[
\frac{1-m}{2}\frac{3500}{168\mathrm{MHz}}=10.19973\mu s.
\]

完整零矢量窗口约20.39947µs。即使Vtest=1V、Vbus=24V，单侧理想间隔仍约9.76563µs。当前低调制量不支持“窗口被压缩到不足3周期”的断言。边沿死区、DRV传播、实际RC/寄生、回流路径仍未实测。

## 5. 64点回放与零偏误差传播

名义3.3V、4096档、G=80、Rs=0.5mΩ：

\[
k=3.3/(4096\cdot80\cdot0.0005)=0.0201416015625\ A/count.
\]

以DC值的单位为安培：

\[
I_\alpha=-k(n_B+n_C-4096)-DC_A,
\quad I_\beta=[k(n_B-n_C)-(DC_B-DC_C)]/\sqrt3.
\]

DC_A≈−DC_B−DC_C；实际回放直接使用记录的DC_A，避免浮点重组误差。

| 指标 | 倒数第二点 | 冻结末点 |
|---|---:|---:|
| ADC2 / ADC3 | 2039 / 2063 | 2051 / 2073 |
| Iα (A) | −0.0473204255 | −0.4903808236 |
| Iβ (A) | −0.00285701593 | +0.02037324756 |
| Vtest (V) | 0.3290801942 | 0.3292039931 |
| Vbus (V) | 23.71150017 | 23.71150017 |
| estimated_ibus (A) | −0.00098510517 | −0.01021247078 |

两路同步上升的直接贡献：

\[
\Delta I_\alpha^{ADC}=-(12+10)k=-0.4431152344A,
\quad \Delta I_\beta^{ADC}=(12-10)k/\sqrt3=0.0232575182A.
\]

加上记录中极小的零偏变化，实际ΔIα=−0.4430603981A、ΔIβ=+0.0232302635A，与换算吻合到浮点舍入量级。该拍零偏只贡献约+54.8µA的α修正。**末点跳变主要来自vector0 ADC共同上升，不是本拍DC滤波突然跳变。**

原生电阻校准估算为：

\[
I_{bus,model}=\frac{Vtest}{(2/3)Vbus}I_\alpha.
\]

逐步按float32计算，完整64点均与捕获吻合；末点重现`−0.0102124707773A < −0.01A`。用24V名义值代替实际23.7115V不能精确重现该数值。末点同时记录system_error=8、motor_error=0x01000000，BDTR由60436变11284（MOE/AOE清除）。这证明本次原生保护执行了关断；**不是实测电源回生电流的证明**。末点相电流范数约0.491A，低于记录的2A限值；本次文件不是先前的过流文件。

前63点全部Iα<0，均值−0.088408585A，范围−0.208716至−0.007306A。约相当于两路合计4.389个计数、每路约2.195计数的共同偏移。它提示不能只解释末点尖峰、忽略前面的负偏置，但整个64点窗口首末跨度仅7.875ms（前63点首末为7.75ms），不足以证明从校准开始就持续反相。

若定义存储零点误差`eB=zstoredB−ztrueB`、`eC=zstoredC−ztrueC`（计数），则：

\[
\delta I_B=-ke_B,\quad\delta I_C=-ke_C,
\quad\delta I_\alpha=k(e_B+e_C),
\quad\delta I_\beta=k(e_C-e_B)/\sqrt3.
\]

两路零点共同偏低，会造成α负偏置、β变化较小。DC滤波τ默认0.2s，系数125µs/0.2s=0.000625。当前一拍DC变化很小，不排除之前vector7采样条件慢慢污染DC值。缺少成对vector7原始值，不能在本阶段证实或排除。

### 制动估算与原始保护输入不能混淆

`MotorControl/low_level.cpp:343`起先求电机Ibus，再按制动设置加入估算吸收电流，最后在`:395`比较**净Ibus_sum**。文件记录的estimated_ibus、runtime_ibus是电机项，不是净值。

离线模型显示：如果制动启用、max_regen_current=0、阻值有效且占空比未饱和，理想软件计算会抵消这一级别的负电流，净值接近0。该捕获没有记录这些配置，因此不能假定它与之前聊天某一时刻的制动配置完全相同。系统错误位证明实际判断触发，但不能单凭该文件重建所有制动配置，更不能据此认定制动电路坏了。

## 7. OV默认0V：定位和仅限24V测试的建议

已确认调用链：

1. `Tupfile.lua:337`给`rehab-v1.3`定义`HW_VERSION_VOLTAGE=0`。
2. `MotorControl/odrive_main.h:87`：默认OV=`1.07f * HW_VERSION_VOLTAGE`，结果0V。
3. `MotorControl/main.cpp:126`的配置清除恢复默认；`:677`起NVM加载失败后走默认。
4. `MotorControl/nvm_config.hpp:29`起V1.3版本0x1301，旧台架/其他板配置不能直接当有效配置加载。
5. `Rehab/platform/runtime.cpp:406`起native/peripherals分支不回填OV；原生fast check正常比较实际母线与0V，造成启动OV错误。

准确结论是**未成功加载配置的V1.3默认OV=0**，不是“每次烧录都会清掉有效NVM”。过压制动渐变默认起止值也受电压宏0影响，但渐变关闭时不参与本次故障。

最小建议位置：现有`Rehab/platform/runtime.cpp`的`early_init()`原生板分支，加一个显式、默认关闭的`V1.3 + peripherals + 24V test`构建选择；在`user_config_loaded_==0`时仅给该测试配置OV=28V。测试UV=20V如需纳入，应同样显式标注，不能冒充48V正式产品参数。构建入口/产物显示24V TEST，避免混用。

有效NVM优先；已保存的0V不能用“发现为0就偷偷回填”覆盖，应报告为配置问题。非测试V1.3、正式48V、V1.2和原板均不受此选择影响。不要简单把全局`HW_VERSION_VOLTAGE`改24：它还涉及硬件variant，且1.07×24=25.68V，并非28V。

本阶段没有实现此建议。测试中仅有纯Python提案模型，覆盖测试配置/非测试配置/其他板型/有效NVM优先。正式实现若获批仍需验证初始化顺序、构建标识和配置版本回归。
